# Поручения: детерминированное ядро, LLM-интерфейс

## Принцип
**Ядро принимает ВСЕ решения детерминированно.** LLM выполняет ровно 3 функции:
1. Отыгрыш в чате (голос/нарратив).
2. Обработка входящего текста → интенты для ядра (и изменение траектории — но решение принимает ядро).
3. Консолидация памяти (вне рантайма).

Интерпретация алгоритма и выбор действия на каждом шаге — **без LLM**, в коде.

## Поручение = алгоритм действий
Поручение (directive) — это алгоритм, который персонаж выполняет **над собой или над другим**. Не разделяем «сотрудник» и «актив»: любой персонаж может быть исполнителем и любым адресатом.

Исполнитель может быть:
- сотрудник (staff/assistant),
- актив (актив исполняет протокол над другим или над собой).

### Виды алгоритмов (spec)
| kind | Что делает | Пример |
|---|---|---|
| `contract` | привести цель к требованиям контракта (тренировать недостигнутые трейты) | «подготовить Миру к контракту» |
| `sequence` | серия действий по порядку | `act_slap, act_punch` |
| `category` | действия по тегам категории | `pain, humiliation` |
| `condition` | действие по условию на метрику + else-ветка | «держи на грани оргазма и унижай» |

### Выбор действия (детерминированный)
- `contract` → действие, тренирующее самый недостигнутый требуемый трейт.
- `sequence` → следующий по списку.
- `category` → действие с целевыми тегами.
- `condition` → действие в зависимости от метрики vs порог.

Завершение проверяется ядром (метрики/трейты достигнуты).

## Входящий текст → интенты (функция 2 LLM)
LLM разбирает текст на два типа интента для ядра:
- **`run_directive`** — выдать поручение: исполнитель, цель, алгоритм. («Подготовь Миру к контракту», «Натренируй на болевые реакции»).
- **`interrupt_directive`** — прерывание/контр-приказ: «Эли требует остановиться», «прекрати». `{interruptedExecutor, requester}`.

Решение (послушается ли) принимает ядро.

## Сопротивление выполнению — детерминированно (личность)
Когда приходит `interrupt_directive`, ядро считает вероятность послушания:

```
compliance =
    подчинение(исполнитель) × авторитет_требующего
    − доминантность(исполнитель) − приоритет_текущего_протокола
    − личный_трейт(саботаж) − лояльность_к_игроку_или_цели
```

Источники:
- **личные качества**: подчинение, доминантность, сила воли, трейт «саботаж».
- **отношения**: отношение исполнителя к требующему, авторитет требующего.
- **статус**: сотрудник отходит от протокола только при ОЧЕНЬ сильных вводных (очень высокое отношение и т.п.).

Если результат ≥ порога → послушался (ядро переключает/завершает алгоритм). Иначе продолжает.

## UI (пункт наблюдения) ✅ реализовано
Карточки активных поручений + прогресс (детерминированно):
- `contract` → сколько трейтов достигнуто из требуемых.
- `condition` → текущее значение метрики vs порог.
- `sequence`/`category` → доля шагов (не отслеживается пошагово).
Кнопка «Завершить». Выдача — только через чат (интент `run_directive`); формы выдачи больше нет.
