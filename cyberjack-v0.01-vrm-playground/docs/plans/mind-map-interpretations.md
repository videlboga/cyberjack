# Mind-map интерпретаций (граф внутреннего мира персонажа)

> Перестройка «слоёв» (A–F) в единый взаимосвязанный граф интерпретаций.
> Слои были источниками текста в промпт; теперь — ноды, влияющие друг на друга
> через консолидацию с детерминированным распространением.

## Цель

Внутренний мир персонажа = майнд-мэп: корень (сценарий жизни) → ветви
(отношения / биография / станция / self) → листья (эпизоды, трейты). Ноды
влияют друг на друга. Консолидация эпизода распространяется на родителей и
кросс-линки (пример: Суми обсудила с Никой побег из дома → меняется тема с
Никой, отношение к Нике, интерпретация эпизода, отношение к себе).

## 1. Факты (неизменяемые атомы) — «земля»

- **Глоссарий → `world_facts`**: 8 терминов (Аномалия, Актив, Калибровка,
  Калибратор, Контракт, Эксперимент, станция, изучение Аномалии) становятся
  атомами-фактами. НИКОГДА не меняются.
- **Эпизоды → `memory_embeddings`** (уже есть, уже неизменяемы).

Персонаж всегда помнит факт «эксперимент = насилие, часто сексуальное».
Интерпретация факта — нода, зависит от трейтов/состояния (мазохист видит
притягательное, травмированный — панический страх).

## 2. Ноды интерпретаций — единая таблица

```sql
interpretation_nodes (
  id TEXT PRIMARY KEY,          -- 'worldview', 'rel:<id>', 'bio:<key>', 'station:<key>', 'self', 'trait:<key>', 'episode:<id>'
  subject_id TEXT NOT NULL,
  kind TEXT NOT NULL,           -- worldview|relationships|biography|station|self|trait|episode
  parent_id TEXT,               -- иерархия
  label TEXT NOT NULL,
  content TEXT,                 -- текущая интерпретация (LLM, 1-3 предложения)
  valence REAL, strength REAL,  -- агрегированные
  fingerprint TEXT,             -- хеш входов (детерминированная dirty-детекция)
  status TEXT DEFAULT 'ready',  -- ready|dirty|generating
  updated_at DATETIME
);
interpretation_links (
  id TEXT PRIMARY KEY,
  subject_id TEXT NOT NULL,
  from_id TEXT NOT NULL,
  to_id TEXT NOT NULL,
  kind TEXT NOT NULL,           -- cross|evidence
  weight REAL DEFAULT 1
);
```

### Дерево (parent_id)

```
worldview (корень: сценарий жизни по Берну)
├── relationships
│   └── rel:<персонаж>          → эпизоды с этим человеком
├── biography
│   └── bio:<тема>              → эпизоды обсуждений этой темы
├── station
│   └── station:аномалия / активы / калибровка / контракты / эксперименты
└── self
    └── trait:<обучение>        (боль, клитор…)
```

Кросс-линки (`interpretation_links`): эпизод «побег из дома», обсуждённый с
Никой, висит на `bio:побег` + `rel:Ника` + `self`. Дерево → DAG.

## 3. Консолидация — детерминированная, ограниченная

1. **Триггер**: новый/изменённый атом → `episode:<id>` помечается `dirty`.
2. **Регенерация эпизода** (1 LLM): content + ассоциации — уже делает
   `subjectiveMemoryEpisodes.queueSubjectiveEpisode`.
3. **Детерминированное распространение** (без LLM): из ассоциаций вычисляем
   затронутых родителей и delta:
   - person-ассоциация → `rel:<person>` (delta = valence × strength),
   - tag-ассоциация → `trait:<tag>`,
   - тема биографии → `bio:<key>`,
   - appraisal/agency → `self`.
4. **Регенерация затронутых родителей** (1 LLM каждый, только |delta| > порог):
   родитель пересобирает content из детей + фактов.
5. **Каскад на `worldview`** (1 LLM, только если значимо).

**Ограничения**: глубина ≤ 2, максимум ~5 нод за консолидацию, порог
значимости |delta| ≥ 0.15. Типичная консолидация = 3–6 LLM-запросов, не 20.
Детерминированно: dirty по `fingerprint`, порядок листья → родители.

## Решения (подтверждены)

1. `worldview` — одна нода-корень (сценарий жизни), агрегирует все ветви.
2. `self` с детьми-трейтами (`trait:<key>`).
3. Стартовые: глубина 2, порог |delta| ≥ 0.15, максимум 5 нод. Потом тест/тюнинг.
4. Миграция: сидируем дерево из существующих данных, затем один проход
   консолидации генерит content.

## Порядок работ

1. Модель данных: таблицы `world_facts`, `interpretation_nodes`,
   `interpretation_links` + репозиторий.
2. Сид: глоссарий → факты; эпизоды/отношения/трейты → ноды.
3. Консолидация: детерминированное распространение + регенерация родителей.
4. UI майнд-мэп (после того, как модель+консолидация работают).
