# Отчет об исправлении проблемы с сохранением позиций нодов в графе

## 🐛 Описание проблемы

В компоненте `ScreenBasedStoryGraph.tsx` не сохранялись положения нодов (экранов) в графе сюжетном. При любом обновлении страницы или перезагрузке данных позиции экранов сбрасывались к значениям по умолчанию.

## 🔍 Анализ причин

### 1. Проблема с мемоизацией
- В `useMemo` использовался `JSON.stringify(s.position)` для создания ключа мемоизации
- Это вызывало лишние пересчеты при изменении позиций
- Позиции могли "прыгать" при обновлении данных

### 2. Проблема с синхронизацией узлов
- В `useEffect` для синхронизации узлов логика сохранения позиций конфликтовала с обновлением данных
- При обновлении компонента позиции из `ref` не всегда корректно применялись

### 3. Проблема с дебаунсингом
- Сохранение позиций происходило с задержкой в 100ms
- При быстрых обновлениях позиции могли теряться

### 4. Отсутствие инициализации позиций
- Не было корректной инициализации позиций при загрузке экранов
- Позиции из базы данных не всегда правильно применялись

## ✅ Внесенные исправления

### 1. Исправлена мемоизация узлов
```typescript
// Было:
const screensKey = screens.map(s => `${s.id}-${s.name}-${JSON.stringify(s.position)}`).join('|')

// Стало:
const screensKey = screens.map(s => `${s.id}-${s.name}`).join('|')
```

### 2. Улучшена логика определения позиций
```typescript
// Приоритет: сохраненная позиция > позиция из БД > дефолтная позиция
const screenPosition = savedPosition || (hasValidDbPosition ? screen.position : {
  x: screenIndex * 400 + 100,
  y: 200
})
```

### 3. Добавлена инициализация позиций
```typescript
// Инициализация позиций при загрузке экранов
useEffect(() => {
  if (screens && screens.length > 0) {
    screens.forEach((screen, index) => {
      if (!nodePositionsRef.current[screen.id]) {
        const hasValidPosition = screen.position &&
          typeof screen.position === 'object' &&
          'x' in screen.position &&
          'y' in screen.position &&
          typeof screen.position.x === 'number' &&
          typeof screen.position.y === 'number' &&
          !isNaN(screen.position.x) &&
          !isNaN(screen.position.y)

        if (hasValidPosition) {
          nodePositionsRef.current[screen.id] = screen.position
        } else {
          nodePositionsRef.current[screen.id] = {
            x: index * 400 + 100,
            y: 200
          }
        }
      }
    })
  }
}, [screens])
```

### 4. Улучшена синхронизация узлов
```typescript
// Всегда используем сохраненную позицию из ref, если она есть
const savedPosition = nodePositionsRef.current[prevNode.id]
return {
  ...newNode,
  position: savedPosition || prevNode.position
}
```

### 5. Убрана задержка при сохранении
```typescript
// Сохраняем позицию немедленно без дебаунсинга
onUpdateScreen(nodeId, { position: newPosition })
```

### 6. Исправлено предупреждение линтера
- Добавлен уникальный ID для чекбокса в форме редактирования выбора

## 🔧 Технические детали

### Архитектура решения:
1. **Ref для хранения позиций** - `nodePositionsRef` хранит текущие позиции узлов
2. **Приоритетная система** - сохраненная позиция > позиция из БД > дефолтная позиция
3. **Немедленное сохранение** - позиции сохраняются в БД без задержки
4. **Корректная инициализация** - позиции инициализируются при загрузке экранов

### API endpoints:
- `PUT /api/story/screens/[id]` - обновление позиции экрана
- `GET /api/story/screens/[id]` - получение экрана с позицией
- `GET /api/story/scenes/[id]/screens` - получение экранов сцены
