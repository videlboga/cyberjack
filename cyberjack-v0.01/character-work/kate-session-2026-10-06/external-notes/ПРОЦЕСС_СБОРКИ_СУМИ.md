## 3. Подгонка тела донора (этап 3) — ⚠️ доведён до v23, результат забракован пользователем

Метод (по хендоффу Кейт): z-ремап по суставным якорям + пер-уровневое масштабирование сечений + rigid-поворот рук. Итерации v1–v23 (`work/shape_v*.py`), каждая с численной верификацией (профили срезов, длинные рёбра, zero-area faces) и превью.

### Что сработало
- z-ремап 1.43→0.82 м по якорям (нелинейный, ноги сохраняют долю)
- rigid-поворот рук из донорской «T вниз-45°» в T-позу Суми (`d @ Rx` — после починки знака) + тоньшение по перпендикуляру к оси руки
- срезка обрубков кистей-варежек по новой оси руки (1681+1681 верт, чистые кольца запястий)
- стопы донора (5 пальцев) сохранены, ужаты 0.16→0.10 длины
- удаление мусора (Icosphere, «серьга»-компонент 177 верт)
- пер-зоновый масштаб (ноги вокруг своей оси, торс вокруг x=0) устранил вырожденные грани (zero-area → 0)
- непрерывный sx(z)/sy(z) вместо полосовых окон убрал «ребра»-алиасинг на ногах

### Чекпоинты и найденные баги (все записаны в скилл blender-rigging)
| Версия | Проблема → решение |
|---|---|
| v1–v2 | наложение полосовых окон накапливалось; не учтена стойка ног → переписан чистый пайплайн |
| v3 | «оторванная кисть» — маска руки недобирала запястье → расширил маску |
| v6 | частичная arm-маска оставляла старый z у торсовых вершин → растянутый торс; фикс: Z-interp для всех |
| v7 | руки укорочены — баг знака вращения `d @ Rx.T` вместо `d @ Rx` → руки улетали вниз |
| v9 | удаление куска до построения numpy-массивов → индексы разъехались; переставил prep до замеров |
| v12full/v13 | bmesh-индексы после delete → маска второго прохода резала ноги; фикс: одна bmesh-сессия |
| v12–v18 | «аккордеон» на ногах в рендерах — **MASK×5 модификаторы донора прятали сломанные зоны**; честные рендеры только со снятыми модификаторами |
| v19–v20 | zero-area faces от схлопывания внутренностей бёдер → per-leg центры; но остались реальные волны ширины ±0.02 м |
| v21 | непрерывный ремап — рёбра ушли, ноги гладкие ✓ |
| v23 | клэмп |Y|>0.135 против «антенн»-подвесок, раздуваемых sy>1 |

### Почему результат — «месиво» (вывод пользователя)
Даже чисто технически гладкий v23 сохраняет донорскую поверхность: взрослый полуреалистичный корпус с экстремальной талией-«песочными часами» (w 0.169 против Суми 0.10), S-изгиб поясницы, сферические груди. Нелинейное сжатие 1.43→0.82 м мнёт её в складки (живот «фартуком», шипы на ягодицах из зажатых прядей, грудь-сфера). Ранние превью выглядели лучше, потому что MASK-модификаторы вырезали дефектные зоны из рендера. Метод хендоффа предполагал близкую по стилю пару «внешность/донор» — у Кейт источники были из одной вселенной, у Суми донор и Tripo-модель стилистически несовместимы.

## 4. Пересборка от sumi_nude (этап 3-бис) — ❌ ремеш не сходится

Решение пользователя после v23: собирать от `sumi_nude` (сварить суп, риг с нуля).

**Что сделано (`work/prep_nude.py`, `work/nude_v1..v4.py`):**
1. Компоненты: 2227 островов → оставлены 8 крупных; тело = 1 компонент (1620 верт после мержа)
2. Сварка remove_doubles 2 мм → 1483 верт, **527 открытых рёбер** (полосовый лист с T-стыками)
3. Итеративная заливка дыр (holes_fill sides=64) ×6 проходов + сварка → открытие застревает на ~530
4. Voxel remesh 3–4 мм → **коллапс: 88–170 вершин** (вместо ожидаемых ~20–40k)

**Причина провала:** суп `sumi_nude` — плотный лист с щелями > вокселя и T-стыками; voxel remesh заполняет только замкнутые объёмы, лист «протекает». Внутри Blender сварить его нечем (MESH_TO_VOLUME-модификатор в 5.2 API недоступен).

**Осталось непопробованным:** внешние сварщики (MeshLab SSR, open3d, instant-meshes) — они закрывают дырявые листы надёжнее bmesh-заливки.

## 5. Проверка родного рига sumi.glb — ❌ сломан

Гипотеза: Tripo-автоскин может быть пригоден, тогда пересборка не нужна.

- Численно: в нейтрали evaluated==rest (max Δ=0) — риг не портит rest ✓
- Тест поворотов (`work/rigtest.py`): **любой поворот кости «взрывает» весь меш** — от «кивка головы» смещаются 25 752 из 29 733 вершин, max_disp до 0.9 м (bind-поза ≠ rest-поза)
- Превью поз (`previews/rigtest/*.png`) подтверждают: полный взрыв геометрии

Вывод: риг Tripo непригоден. Веса родного рига не источник.
