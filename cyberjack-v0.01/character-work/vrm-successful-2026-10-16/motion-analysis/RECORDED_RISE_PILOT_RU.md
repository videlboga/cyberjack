# Пилот записанного перехода

Просмотр: http://127.0.0.1:8782/character.html?demo=recorded-rise — Две кнопки: «Записанный подъём» и «Прежнее смешивание». Обе используют одинаковую исходную позу.
Старый вариант для того же сидячего начала: http://127.0.0.1:8782/character.html?demo=rise .

`tools/recorded-rise.mjs` выбирает сидячий участок проверенного перехода `5c067507ed8dca6d85fcd5f9` (Stand Up 1) и следующий участок до стойки. До записи добавляется отдельный вход к её начальному кадру. Записанная часть не проходит context correction, joint projection, whole-body solver, trajectory warp. Меняются только общий постоянный поворот вокруг вертикали и горизонтальное смещение корня: вход записи совмещается с направлением персонажа. Исходное время сохраняется. В плеере для этого участка используются обычный quaternion slerp и отключены дополнительные контакты VRM коленей/стоп. Ретаргетинг на VRM и spring bones остаются.

Это один маршрут будущего графа, не универсальный контроллер. Вход пока процедурный (1.8 с в сохранённом примере), подъём записанный (~3.29 с). Изменение опор внутри записи не вычисляется заново. Новых гарантий физического равновесия нет.

В обычном интерфейсе есть переключатель «Записанный подъём с пола · пилот», по умолчанию выключен. Срабатывает для низкого сидячего положения и команды встать без перемещения в том же этапе. Если исходные ограничения целевой позы несовместимы с записанной стойкой, используется прежний планировщик; ограничения не удаляются. Для сравнения используйте сохранённый прогон, он исключает разброс языкового плана.

Проверки: `tools/recorded-rise.test.mjs` сверяет все локальные вращения суставов, общий поворот корня, локальные позиции/масштабы с исходными кадрами (погрешность нормализации quaternion <1e-12). Проверены также прежний rise-preparation и transition-warp. Это проверка сохранности записи, а не оценка визуального качества.
