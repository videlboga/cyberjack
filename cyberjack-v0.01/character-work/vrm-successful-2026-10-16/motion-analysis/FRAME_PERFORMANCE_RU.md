# Кадры вьювера, 2026-10-23

Проблема воспроизведена на удержании обеих ладоней на ягодицах после наклона: около 1.5 FPS, draw ~672 мс/кадр. Даже статичная исходная поза проходила полный avatar-space IK, поиск по коже, проверки пересечений и настройку кистей каждый кадр.

Изменения:
- `review/avatar-pose-cache.mjs`: результат retarget/contact-прохода переиспользуется только при одинаковых исходных p/q/s, целях, весах контакта, опорах, режиме физики, положении актёра и предметах сцены. Восстанавливаются кости и положение VRM перед обычным слоем настроения, морганием и анатомическими ограничителями. Изменение позы/контакта инвалидирует результат; временного удержания устаревшего решения нет.
- `review/surface-search.mjs`: точный KD-поиск ближайшего образца кожи вместо полного перебора для каждого пробника на каждом шаге IK. Индекс строится заново для каждого деформированного облака; число пробников и пороги не уменьшены, порядок равных расстояний сохранён.
- Скрытый документ прекращает обновлять/рисовать сцену. Невидимый скелет и выключенная схема опор не строят свою геометрию. Статичный текст анатомической точки не заменяется в DOM каждый кадр.
- У существующего ограничителя 30 FPS убрана чувствительность к округлению времени RAF; добавлена строка фактического FPS/времени draw и render (`#frame-performance`, JSON в data-report).

Сохранённая проверка: `/character.html?demo=frame-performance`; контроль без кэша `&poseCache=off`. Используется `/performance-fixture.json`, та же исходная поза и сохранённый план, без нового языкового запроса. Временная контрольная вкладка после проверки закрыта.

В двух одновременных VRM-вебвью после кэша получилось 21–23 FPS, draw ~17–18 мс, 100% попаданий кэша на удерживаемой позе. Контакты остались неблокированными; разница зазоров ~1 мм (исходный solver итеративно меняет решение между кадрами). Замеры и контакты: `artifacts/viewer-frame-performance/comparison.json`. Это проверка текущего статического контакта, не гарантия FPS для каждой движущейся сцены.

Проверки: `tools/avatar-pose-cache.test.mjs` — восстановление и инвалидация всех каналов/контекста; `tools/surface-search.test.mjs` — точное совпадение глубины, контактов и ничьих с линейным поиском на 500 пробниках; `tools/skin-clearance.test.mjs`; реальная Mira: `tools/check-avatar-contact.mjs artifacts/buttocks-kneeling-regression --skin-safety --arm-limits --ramp` — обе кисти безопасны, нормали и ограничения суставов сохранены.

Рабочая вкладка без второй тестовой VRM: около 25 FPS. Временная вкладка закрыта, последняя сохранённая поза восстановлена через frame-performance без нового языкового подбора. При проверке естественной команды обнаружена ещё форма `bent forward`; нормализация наклона расширена также на неё, `forward bend` и `bowed forward`, с теми же проверками опор и обеих кистей.

Первичный поиск точки контакта дополнительно перестал вызывать `skeleton.update()` для каждой из тысяч вершин: матрицы скелета обновляются один раз на mesh перед проходом, в котором кости неизменны. Все вершины по-прежнему проверяются. Повторная проверка контактов Mira с ramp/skin-safety/arm-limits прошла. В браузере сохранённый переход завершился за время проверки (~8 с), вместо длительного покадрового продвижения при тяжёлом IK; отдельный первый кадр захвата контакта всё ещё может быть заметно дороже idle.

## Движущиеся контакты: второй проход оптимизации

Профиль реальной Mira показал большое время в compose/multiplyMatrices/updateMatrixWorld. Внутри поиска поворота предплечья неизменная матрица родителя кисти читалась заново на каждом из 37 вариантов. Теперь она вычисляется один раз. При пробных ограничениях одной руки обновляется только её ветка с предками, вместо всей VRM. Финальный общий проход ограничителей оставлен. Пробники кожи ладони обновляют ровно используемые boneMatrices; полный renderer upload остаётся штатным.

Сравнение одной и той же последовательности весов на реальной Mira (`check-avatar-contact`, buttocks-kneeling-regression, skin-safety + arm-limits + ramp): полный обход сцены 9433 мс; локальный обход 4929 мс; локальный с частичным обновлением CPU-пробников 4569 мс. Это сумма solver-проходов, не задержка одной команды. JSON отчётов совпал с baseline по всем полям (числа с допуском 1e-9, найдено 0 отличий).

Браузерный повтор показывает оставшуюся проблему: при движении без попаданий в кэш встречаются окна 3–5 FPS с draw 195–248 мс и начальные поиски контакта до 2.8–3.7 с на кадр. Удержание контакта возвращается примерно к 18–23 FPS. Таким образом ускорение подтверждено, но отсутствие длинных кадров ещё не достигнуто: следующий необходимый шаг — разделить первичный перебор контакта на порции/вынести его из потока отрисовки, сохранив проверки и согласованное применение готового решения. Нельзя выдавать статичный кэшированный idle за решённую производительность переходов.

Проверки: forearm-search-fast.test.mjs (40 нормалей, разные шаги и wrist limits), arm-world-update.test.mjs (все world-матрицы), probe-skin-update.test.mjs (точные деформированные вершины), skin-clearance.test.mjs; actual-avatar ramp для buttocks-kneeling-regression и hands-head-regression — PASS. История 40 окон FPS/draw/maxDraw/cache теперь доступна в DOM #frame-performance[data-history].

## Порционный поиск контактов

`vrm-body-touch.solve()` теперь является генератором: облако кожи строится небольшими блоками; поиски точки, полюса локтя, отступа ладони и ориентации кисти уступают управление между пробами. Синхронный `apply()` для тестов остаётся точным исчерпывающим проходом того же генератора. Количество кандидатов, проверки и пороги не менялись.

`cooperative-pose-solve.mjs` выполняет поиск с бюджетом 6 мс между отрисовками (одна неделимая проба может выйти за бюджет). Пробные q/p/s сохраняются отдельно; перед кадром возвращается последняя законченная поза. Возобновление восстанавливает и кости, и скиннинг, чтобы рендер/мимика не вмешивались в решение. При смене входа старая задача отменяется. Время движения приостановлено до готовности проверенного результата; моргание, настроение, камера и UI продолжают работать. Это устраняет многосекундную блокировку страницы, но не сокращает само количество работы и может увеличивать время завершения контакта.

Проверки: `tools/cooperative-pose-solve.test.mjs` — бюджет, невидимость проб, продолжение после внешних изменений, отмена и откат ошибки. `check-avatar-contact.mjs --cooperative` намеренно меняет кисти и обновляет скелет между порциями поиска; финальные отчёты должны совпасть с синхронным baseline, а проверки кожи и суставов пройти.

Финальная браузерная проверка без фонового CPU-теста: при надписи «Расчёт контакта · поиск порциями между кадрами» — 22 кадра / 1.031 с (~21.3 FPS), средний draw 25.6 мс, максимальный 34.5 мс. Это активный поиск (не idle/cache hit). Повторный прогон той же финальной версии завершился обеими ладонями на поверхности; контактные отчёты сохранили исходные значения. Снимок окон/статуса: `artifacts/viewer-frame-performance/sliced-search.json`. Начальная загрузка/привязка модели в этот замер не включена. Общая стоимость сложного контакта пока остаётся высокой; распределение по кадрам отделяет её от отзывчивости UI.
