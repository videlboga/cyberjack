# POSE1 — формат записи позы

Одна поза = набор направлений по гуманоидным слотам плюс угол скрутки вокруг каждой кости.
Ни позиций, ни длин, ни rest-ов ригов внутри нет: формат не знает ни про Koikatsu, ни про
нашу базовую модель, ни про её пропорции.

```json
{
  "format": "POSE1",
  "subject": {"clip": "<id>", "t": 0.5, "source": "koikatsu-cf_j"},
  "frame": "character: X=right, Y=forward, Z=up",
  "slots": {
    "leftUpperArm": {"d": [0.31, -0.12, -0.94], "roll": 18.4},
    "leftHand":     {"d": [0.52,  0.17,  0.83], "roll": -71.2}
  },
  "extras": {"parametric": "not touched"}
}
```

## Поля

- `d` — единичное направление кости в **анатомической рамке**: `a` = влево (правое бедро → левое),
  `f` = вперёд (стопа → носок), `u` = вверх (таз → голова). Оси берутся **из REST-скелета**, а не
  из текущей позы: рамка, построенная по позе, поворачивается вместе с телом и съедает разворот.
  Оси сопоставляются по смыслу (лево→лево, перёд→перёд), поэтому левосторонность координатных
  систем источника и цели может быть любой — кресты и перевороты не нужны.
- `roll` — скрутка, переносится парой кватернионов источника `q` и `qrest` (текущий и rest).
  **Накладывается только на кисти.** На остальных костях скрутка не читается глазом, а из-за
  разницы rest (T у источника, A у цели) даёт паразитный поворот: направления уезжали на 40–60°.
  С ограничением «только кисти» ошибка направлений по всем 20 слотам ≤ 0.5°.
- `slots` — только 22 гуманоидные кости (таз, 3 позвонка, шея, голова, 2×3 руки, 2×4 ноги).
  Пальцы, параметрика, язык и одежда в формат не входят и не затрагиваются.

## Почему так

Локальные повороты не переносятся: у источника rest — T-поза, у нас — A, и «5° от T» ≠ «5° от A».
Проверено: поза, записанная локальными поворотами, даёт руки вниз вместо рук к груди.
Направления такого не несут — «бедро смотрит вниз-вперёд» одинаково на любой модели.

## Почему одни позы совпадали, а другие выворачивались

Замерено: рамки rest у источника (T-поза, `cf_j_*`) и у нашей модели (A-поза, `rig_E`) расходятся
не на скрутку вокруг оси кости, а на **посторонний поворот 64–161°** вокруг перпендикулярной оси
(таз 96°, кисть 93°, стопа 161°). Перенос поворота кватернионом при таком расхождении даёт ошибку,
**зависящую от позы**: в одних конфигурациях она компенсируется, в других складывается. Отсюда
«две позы нормальные, три вывернутые» на одном и том же конвейере.

Правило, которое это снимает: скрутку не переносить, а **вычислять геометрически**. Для каждой
кости ось сгиба = нормаль плоскости, образованной направлением кости и направлением её
продолжения в позе (`d × d_child`). Для концевых костей (кисть, стопа, макушка) берётся ось
родителя. Направления при этом остаются точными: самопроверка 0.0°.
