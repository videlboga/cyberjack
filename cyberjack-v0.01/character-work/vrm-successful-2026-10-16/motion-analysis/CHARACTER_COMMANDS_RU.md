# Управление персонажем естественными командами · первый стенд

Открыть: http://127.0.0.1:8782/character.html

Это отдельная сцена рядом со смешиванием, а не изменение игрового ядра. Один персонаж Mira, начальная стоящая idle. Можно вводить произвольный текст, последовательно менять позу, поднимать конечности, перемещаться и поворачиваться. Следующая команда получает фактические текущие локальные трансформации 63 костей, а не только название последнего клипа. «Остановить здесь» сохраняет промежуточную позу; сброс возвращает исходную idle.

## Как работает

1. `tools/command-language.mjs`: существующий LLM-провайдер из конфигурации VRM-playground переводит текст в последовательность геометрических условий. Список ID действий, регулярные выражения для команд и таблица «фраза → клип» не используются. Словарь ограничивает измеримые свойства скелета, а не типы команд: высоты головы/таза/суставов, наклон корпуса, сгибы/разведение конечностей, положение ступней, положение и ориентация корня. Неподдерживаемое свойство не исполняется по догадке. Ключи остаются на сервере.
2. `tools/command-planner.mjs`: поиск по независимым кадрам всего индекса контекстов. Для новых целей отдельно ищутся доноры частей тела, затем проверяется полная композиция с сохранением текущей базы. Если нужна смена опоры/базы, используется согласованная исходная поза целиком. Т-цепочки фильтруются; исходные архивы проверяются по SHA-256. Названия клипов не определяют геометрическую пригодность.
3. `review/command-pose.mjs`: композиция цепочек, FK, измерения, нормализация положения, непрерывная интерполяция вращений и трансляций.
4. `tools/command-trajectories.mjs`: поиск переходных отрезков с близким началом и подходящим концом, проверка скачков. Если отрезка нет, используется явно обозначенное плавное смешивание поз. Для перемещения подбирается совместимый клип ходьбы и отдельно управляется корень. В рамках одной команды `translation` и `yaw` — абсолютные цели относительно системы координат в начале команды; они не суммируются повторно между этапами.
5. `review/character.js`: очередь этапов, VRM-ретаргетинг, камера, удержание результата, остановка и продолжение из текущей позы. План целиком проверяется перед стартом. Если хотя бы один этап не собран, сохраняется текущая поза и показываются невыполненные условия.

Поиск выполняется в worker (`command-service.mjs`, `command-worker.mjs`) и не блокирует HTTP-сервер и просмотр сцены. Первый поиск загружает индекс; это дороже последующих запросов. Сеть/LLM также добавляют задержку.

## API

- GET `/api/character/state`: исходный скелет, поза, геометрия и положение.
- POST `/api/character/command`: `{text, state?}` → проверенный план, этапы, источник каждого этапа, условия, целевые координаты, при наличии исходная траектория.

Используется существующая `.env` соседнего `cyberjack-v0.01-vrm-playground`, без изменения файла. Настройки стенда можно переопределить через `COMMAND_MODEL`; `COMMAND_LLM_PROVIDER=ollama` включает локальный транспорт с `COMMAND_OLLAMA_URL`. Без ключа облачного провайдера используется локальная Ollama. Языковой разбор не подменяется скрытым распознавателем ключевых слов при ошибке сети.

## Проверено

`node tools/command-system.test.mjs` — валидация, непрерывность поз, отказ для недостижимой цели без изменения состояния, координаты без накопления перемещения, источник ходьбы.

`node tools/character-ui-qa.cjs` — реальный браузер, VRM и действующий LLM:

- Стоя → сесть → выставить обе ноги вперёд.
- Из этой сидячей позы → поднять левую руку: сохранение базы и смешивание цепочки руки.
- Стоя → на колени → наклониться к земле головой.
- Из предыдущей позы → встать → пройти 2 м → повернуться направо; итог `[0,2]`, 90°.

Снимки и полные планы: `artifacts/character-command-qa/`. Ошибок JavaScript в прогоне нет. Ссылки на стенд добавлены в классификатор, библиотеку и смешивание.

## Границы текущего этапа

- Это геометрическое управление. Точное касание лбом, закрепление стоп/кистей, препятствия, равновесие и контактная динамика пока не решаются. `headHeight` — высота кости головы, не измерение поверхности лба.
- Если подходящий переходный клип не найден, переход процедурный. Гладкость не доказывает естественность или отсутствие самопересечений.
- Конечная поза по умолчанию удерживается; автоматический поиск подходящего живого idle для каждого нового положения ещё не добавлен.
- Перемещение соединено с библиотечной ходьбой, но длина шага и фиксация стоп ещё требуют согласования.
- Нет выполнения команд через игровое ядро, объектов/партнёров, правил доступности, лицевых команд или речи в этой сцене. Существующий интерфейс игры не изменён.

Следующий слой: контактные цели и IK поверх плана, привязка устойчивых idle, оценка качества переходов и затем подключение к игровым правилам исполнения.

## Доработка естественности · 20 октября

- Подключена существующая контекстная коррекция (`command-correction.mjs` → `context-search.mjs`): вторичные части тела согласуются с результатом, при этом основные условия команды защищены. При выпрямлении ног руки могут освободить колени заранее.
- Геометрический индекс дополнен ориентацией груди/лица и сгибами локтей: 53 694 клипа, 161 077 кадров, без ошибок чтения. Данные: `data/command-orientation.jsonl`, генератор `tools/build-command-orientation.mjs`. Теперь различаются положения на животе и на спине; для верхней части тела можно сохранить таз и ноги текущей базы.
- Семантика уже присутствовала: 120 244 строки поиска, 108 777 сценических меток и 679 связок контроллеров. Это преимущественно названия и контекст источника, а не проверенные описания движения. `tools/command-semantics.mjs` использует их вместе с измеренной геометрией; реакционные слои не выбираются самостоятельной позой.
- Для рассматриваемых источников дополнительно сохраняются описания назначения, стиля, реквизита и побочного действия в `data/command-semantic-descriptions.json`. Они выведены языковой моделью из имени и метаданных, имеют `verified: false` и не являются результатом просмотра видео.
- Нейтральные переходы и ходьба проходят отдельную проверку назначения: боевые, оружейные и акробатические движения не используются как обычная ходьба. В браузерном прогоне выбрана `Female Walk`.
- Переходы ищутся по более плотной траектории, с согласованием начального и конечного положения. Если подходящего отрезка нет, остаётся процедурный переход; освобождение рук и изменение опоры разводятся во времени.

Проверка: `command-naturalness.test.mjs`, `command-system.test.mjs`, `context-correction.test.mjs`; браузерный прогон `tools/character-natural-ui-qa.cjs` с действующим языковым разбором. Все четыре сценария (сесть/вытянуть ноги; встать/пройти/повернуться; колени/поклон; спина/подъём на руках) завершились без невыполненных геометрических условий и ошибок JavaScript. Планы и промежуточные снимки: `artifacts/character-natural-motion/ui/`.

Это проверка геометрических условий и визуальная выборка, а не гарантия контактов: точная поверхность лба, перенос веса, закрепление ладоней и стоп, самопересечения и плавная остановка ходьбы требуют следующего слоя IK/контактов. Конечные позы пока удерживаются, а не получают автоматически согласованный живой idle.

### Ориентация при последовательных командах

Исправление 20 октября: воспроизведено сохранение условий «лёжа» при последующей команде «сесть». Причина в языковом плане: он переносил старые torsoInclination/chestUp/headHeight, и поиск корректно считал текущую лежачую позу подходящей ошибочному заданию. Теперь каждый этап языкового плана обязан отдельно задать `worldTorso` (числовые диапазоны наклона к мировой вертикали и ориентации груди). Эти условия заменяют старые ограничения ориентации. Промпт явно требует отменять несовместимые высоты головы/груди при смене положения. После коррекции и построения перехода итоговая поза повторно измеряется и проверяется. Регрессия в `command-naturalness.test.mjs` проверяет, что повёрнутая в горизонтальную плоскость сидячая конфигурация не считается сидением. Браузерная последовательность: `tools/character-orientation-ui-qa.cjs`.

Дополнительно: прежние числовые ограничения больше не передаются языковой модели как цели следующей команды — только фактические измерения, положение и профиль. Это устраняет копирование старого headHeight/ориентации после команды сменить позу. Незаданные конечности сохраняются механизмом выбора и смешивания относительно текущего скелета, а не переносом всех прошлых ограничений.

### Ошибки контракта языкового разбора

Неизвестное имя геометрического свойства или некорректный диапазон теперь включается в диагностическую ошибку. Языковая модель получает одну попытку исправить JSON для исходной команды; цели не отбрасываются и неизвестные параметры не заменяются молча. Повторный неверный ответ отклоняется. При новом запросе интерфейс очищает прошлый список шагов и геометрические детали, чтобы ошибка нового запроса не выглядела результатом предыдущего действия. Проверки ремонта и отказа после двух неверных ответов входят в `command-naturalness.test.mjs`.

Одиночная просьба сменить позу теперь задаёт одну конечную цель без придуманных разборщиком обязательных промежуточных поз. Для «ляг на живот» не требуется предварительно найти отдельно строго заданный поклон с коленей. При повторном планировании сохраняются только условия исходной просьбы; примеры контактов из инструкции не должны становиться дополнительными требованиями. Переходный механизм по-прежнему отвечает за путь, его контактные ограничения остаются описанными выше.

Смена опорной системы определяется отдельно: большой переход ориентации корпуса или переворот грудью вверх/вниз отключает автоматическое сохранение ног и высоты таза от прежней базы. Это предотвращает «лёжа только верхней половиной» с поднятыми ногами из сидячей позы. Для обычного положения на животе учитываются низкие грудь/таз и расположение коленей/ступней около пола, без обязательного отдельного этапа вставания на колени.
