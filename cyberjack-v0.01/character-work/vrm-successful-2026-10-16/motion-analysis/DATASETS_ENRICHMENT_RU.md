# Обогащение библиотеки внешними датасетами движений · 2026-10-20

Оценка: какие публичные датасеты закрывают три известные дыры — **описания**, **переходы**, **простые движения** —
и что из этого реально импортируется в `koikatsu-native-v1` без перелома контракта смешивания.

## 1. Факты о нашей библиотеке (сняты с живого каталога)

```
total 120 244 · playable 117 375 · bundles 1 361
mods 90 088 · h 23 279 · studio 5 434 · action 1 015 · adv 216 · map 96 · custom 74 · vr 4
rig: male 63 600 · female 47 372 · shared 6 403 · object 2 869
```

- Формат клипа `koikatsu-native-v1`: локальные кватернионы `cf_j_*`, **rest = identity**, 30 fps, типичная длина 0.67–1.33 с (петли).
- Риг `p_cf_body_bone` = 580 костей в `source_rigs.json`, анимируется подмножество (~171); отображение на humanoid уже есть — `vrm_studio_assets/bone-map.json`, 56 пар `cf_j_* → VRM`.
- «Простые движения» по факту отсутствуют: `category=action` (1 015) — это `Idle_*` и `*Loop` фазы H-сцен, `adv` (216) — тоже `Idle_*`. Ходьбы, бега, приседания, вставания, поворота корпуса в каталоге нет.
- Базы смешивания — 7 статических поз. Композиция = `base ∘ delta` по маске; смены базы нет — значит переход между состояниями сегодня только slerp/скачок.
- Переходы: phase-клипы (`Start/Drop/Insert/OUT/Stop`) существуют только внутри H-сцен и не годятся как межбазовые.
- Описания: измерены geometry/anatomy/accents (`energy`, `speed`, `body.inclination`, `presented.part`), но осей **affect/style (valence/arousal/tension)** нет, свободного текста для 90 088 `mods` нет.

Вывод по лицензиям: **коммерчески чистые источники — CMU и 100STYLE**. Остальное либо NC, либо в чужом пространстве (SMPL), либо и то и другое.

Почему текстовые датасеты (HumanML3D/BABEL) не тащим: их retrieval-модели работают на SMPL-фичах и описывают повседневные действия. Наши клипы — короткие петли H-поз; ближайший сосед по эмбеддингу даст «sitting» вместо нужного «наездница, отклонясь назад, рваный темп». Выигрыш есть только у text2motion-генератора, которого у нас нет.

## 3. Трек A — оси стиля/аффекта из 100STYLE (дешевле всего, нужнее всего mixer'у)

Идея: 100STYLE — единственный датасет, где **контент фиксирован, а меняется только стиль** (тот же актёр, те же FW/BW/ID, 100 манер). Это позволяет не гадать про «напряжённая/расслабленная поза», а измерить, какие признаки реально разделяют стили.

1. Считать на 100STYLE признаки, которые у нас уже есть в измеренном виде: амплитуда конечностей, частота шага, темп (endpoint speed), наклон корпуса `body.inclination`, размах рук, ширина шага, доля статики.
2. Проверить разделимость: матрица стиль × признаки, отчёт «какой признак что различает» (числа, не впечатления).
3. Перенести те же признаки на наши клипы (пересчёт не нужен — лежат в `library-search.json` / `library-annotations.jsonl`).
4. Отдать в mixer оси: `style.tempo`, `style.amplitude`, `style.lean`, `style.steadiness` + производные метки (резкий / плавный / усталый / игривый / напряжённый).
5. Оформление — по правилу проекта: **отдельный слой** (`data/style-axes.json` + свой builder + свой стор ревью), не правка `library-annotation.mjs` — иначе `annotationFingerprint` убьёт все сохранённые ревью.

Пилот: 20–30 клипов с известным содержимым, таблица «ожидалось → получилось» (как в `motion-analysis-labeling.md`).

## 4. Трек B — простые движения и базовые позы из CMU

Зачем: mixer'у нужны **полные позы** как база (delta-слой базой быть не может) и нужен реальный локомоушен.

1. Отобрать 60–100 клипов по текстовому индексу CMU: idle/stand, sit-down, stand-up, walk, run, turn, crouch, kneel, pickup, wave.
2. Ретаргет CMU (FBX/BVH, T-поза) → `p_cf_body_bone`: ядро по `bone-map.json` (56 пар), остальные кости — rest (это совпадает с нашим форматом `rest = identity`), длина конечностей выравнивается по rest-offset костей, а не масштабом.
3. Запечь в `koikatsu-native-v1` 30 fps, зеркало по `tools/animation/ANIMATION_PROVENANCE.md` (generic → `[-x,-y,z,w]`).
4. Каталог: новый источник (`source: external/cmu/<path>`), synthetic `pathId` = hash файла, `category: action`, `rig: female`, provenance + license в записи.
5. Прогнать цепочку `build-index.mjs` → `build-anatomy.mjs` → `build-library-annotations.mjs` → `build-hentai-labels.mjs` (~30 мин).

Результат: 7 статических баз → десятки полных баз + ходьба/бег/поворот; это напрямую расширяет число комбинаций композиции.

## 5. Трек C — переходы

- **Локомоция**: 100STYLE `TR1/TR2/TR3` — готовые переходы идти↔бежать↔стоять↔шаг в сторону, в 100 стилях. Это ровно то, чего нет.
- **Смена состояния тела**: CMU sit-down / stand-up / lie-down / get-up / turn.
- Запечь как `category: transition`, 40–60 клипов, 0.5–2 с, метки `from`/`to`/`style`.
- Mixer получает цепочку `base → transition → base` вместо slerp-склейки. Контракт `mix-core` менять не требуется — это данные, не код; важно не лезть в файлы, которые правит агент по смешиванию.
- H-специфичные переходы (поза A → поза B внутри библиотеки) внешними данными не закрываются и не должны: это задача mixer'а (in-between по нашим же клипам).

## 6. Что получает система смешивания (контракт поставки)

На каждый импортированный клип в каталоге/аннотации:

```json
{ "id": "...", "category": "action|transition",
  "rig": "female", "fps": 30, "duration": 1.5,
  "base": true, "delta": false,
  "from": "stand", "to": "sit",          // только transition
  "style": {"tempo": 0.4, "amplitude": 0.7, "lean": 0.1, "steadiness": 0.8},
  "provenance": {"dataset": "100STYLE", "style_name": "Angry", "movement": "TR1",
                 "license": "CC BY 4.0", "commercial": true}
}
```

`commercial` — обязательное поле: коммерческая сборка фильтрует по нему одной строкой, NC-контент физически не попадает в поставку.

## 7. Чего не делать

- Не импортировать LAFAN1 (ND) и AMASS/Motion-X/MotionMillion (NC + SMPL-пространство).
- Не вводить второй bone space в mixer'е: внешние клипы обязаны приходить уже запечёнными в `cf_j_*`. Известная проблема «mixer на library rig vs bank на Koikatsu space» иначе удвоится.
- Не править `library-annotation.mjs` / `build-library-annotations.mjs` — fingerprint.
- Не тащить текстовые аннотации HumanML3D/BABEL в продукт: лицензия research-only, а польза для H-клипов близка к нулю.

Риск №1 — ретаргет (T-поза CMU vs A-поза Koikatsu, разная длина сегментов). Поэтому шаг 0 обязателен: без числовой проверки батч не запускать.
Риск №2 — схема каталога ждёт zipmod-происхождение (`source`/`pathId`); для внешних клипов нужен synthetic pathId — проверить, что `build-index.mjs` и `query.py` их принимают, до батча.
Риск №3 — 28 костей в 100STYLE: кистей, пальцев и лица нет → годится только для базы/локомотива/переходов, акт-слоями быть не может.
