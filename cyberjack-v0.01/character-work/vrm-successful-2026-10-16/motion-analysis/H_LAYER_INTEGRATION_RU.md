# Семантический слой в подборе команд

Подключение: `tools/h-layer-evidence.mjs` → `tools/command-semantics.mjs`.
Исходные `data/h-layer*` не изменены.

- Поиск только по ID клипа. Повторяющиеся имена не связывают разные ассеты.
- Старые ссылки контроллера по общему имени скрываются для неоднозначных имён.
- `layerKind` из количества сцен не используется как запрет целой позы.
- `derived_from_position` хранится как контекст сцены, не анатомия клипа.
- Прямые VLM-описания учитываются при согласии >=0.75; перенесённые метки
  не используются для визуальных выводов. Согласие не означает истинность.
- Явная Т-поза и посторонние действия получают мягкий штраф при выборе целой
  позы. Частичные доноры не штрафуются за движение других частей тела.
- Для цели-позы есть небольшой приоритет визуально статичных клипов.
- Геометрия, опоры и проверки результата сохранены. Описания не добавляют
  условия в команду. `act` пока выводится с происхождением, но не является
  самостоятельным анатомическим ограничением.
- `stage.semantics.hLayerRanking=false` отключает новые штрафы для сравнения;
  исправление неоднозначности связей остаётся включено в обоих режимах.

## Проверки

`node --test tools/h-layer-evidence.test.mjs tools/pose-retrieval.test.mjs`

`node tools/h-layer-ranking-benchmark.mjs` сохраняет
`artifacts/h-layer-integration/ranking-ab.json`.
Это сравнение этапа retrieval, не доказательство естественности анимации.
В четырёх пробах (сесть; вытянуть ноги сидя; на колени; лоб к полу) первые
кандидаты совпали: у них отсутствуют прямые VLM-описания. Нельзя заявлять
улучшение этих финальных поз по этому результату. Прогретый подбор занимал
около 0.10–0.13 с; первый запуск также загружает старые индексы и новый слой.

Следующая разметка должна прицельно покрыть частых финалистов планировщика,
а не переносить метки между всеми клипами с одинаковым именем. Полезны окна
движения, активные цепочки костей, реальные опоры, предметы и характер действия.
