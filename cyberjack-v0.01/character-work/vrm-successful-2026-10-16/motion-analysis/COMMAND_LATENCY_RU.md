### Целостность составной команды

Проверенные этапы публикуются только после успешной проверки всей цепочки и подготовки финального idle/действия. При отказе следующего этапа промежуточные этапы не запускаются. Это сознательно заменяет прежний ранний запуск, который оставлял персонажа в незавершённой позе; старт теперь ждёт полного расчёта. Клиент при отказе без запущенных этапов восстанавливает прежний idle. Регрессии проверяет `tools/command-progress.test.mjs`: отказ второго этапа не публикует первый, успешное разгибание ног публикует цепочку вместе с terminal motion.

### Локальное восстановление после отклонения кандидата

Планировщик повторяет геометрический этап до трёх раз: сначала без необязательной контекстной коррекции (если она применялась), затем исключает отклонённый исходный клип из подбора. Цели, проверки пересечений и атомарный запуск всей команды сохранены. Для предметных опор и явно запрошенных записанных траекторий этот резерв пока не применяется. Успешный первый вариант не запускает дополнительные поиски; неудачные варианты увеличивают время расчёта. Тест `tools/command-recovery.test.mjs`; альтернативные источники для сидения/разгибания проверены в `artifacts/seated-leg-extension-regression/alternative-sources.json`. Это не гарантия выполнения любой анатомически возможной команды и не поиск произвольного графа переходов.

## Явная сторона локальной правки ноги

Короткий MOTION_INTENT_SYSTEM поддерживает raised с обязательным side; числовой диапазон подъёма компилируется относительно текущей высоты стопы. Подъём ноги больше не исключается из motion-facts только из-за глагола «подними». Компилятор передаёт semantics.localLegSides; validateIntent сохраняет только одиночную допустимую сторону; legOnlyEdit предпочитает её распознаванию слов в описании. Старый текстовый резерв понимает ногу/ножку. Неуказанная сторона в raised отклоняется для полного разбора, не превращается молча в обе ноги. Для raised не добавляется фиксация поднимаемого колена к полу.

Тест tools/local-leg-intent.test.mjs: left/right, перефразировка без имени стороны, «ножка», сохранение выпрямленного колена, исключение команд со вставанием/наклоном корпуса. Это единичный замер, не SLA.

## Единый языковой запрос — 2026-10-23

По умолчанию `interpretCommand` использует один запрос: компактный семантический JSON → локальная компиляция → прежние проверки геометрии. Автоматического перехода compact → general больше нет. Старый протокол доступен явно через `interpretLegacyCommand` / `COMMAND_LANGUAGE_MODE=legacy`; его регрессионные тесты вызывают именно этот протокол.

`tools/semantic-intent.mjs` хранит контракт и компилятор. Обычные цели описываются качественно; действия и требуемые траектории остаются свободным английским текстом. Для сложной геометрии тот же ответ может содержать прежние constraints/worldTorso — это сохраняет возможность описать цели вне локальных правил без второго запроса. Неизвестные условия не подменяются idle. Контакты рук, сторона тела и цели предыдущих этапов сохраняются. Активность сама по себе не должна менять позу.

Для OpenRouter добавлен `provider.sort=latency` (документация: https://openrouter.ai/docs/guides/routing/provider-selection). Другие совместимые endpoint не получают специфичные поля маршрутизации. Модель не менялась. Перед маршрутизацией по задержке реальные ответы колебались примерно 3–12 с; после неё один проход шести команд без кэша дал 0.89–2.46 с, локальная компиляция 0.6–5 мс. Это измерение языкового этапа, НЕ всей подготовки движения и НЕ гарантия SLA. Поведение провайдеров меняется.

Замеры с исходными ответами и метриками: `artifacts/semantic-parser-v1/benchmark.json`; повторение: `node tools/benchmark-semantic-parser.mjs`. `timings.languageDetails` в результате планировщика теперь содержит запросы, провайдера, токены, задержку запроса и компиляции. Проверенный смысл кэшируется отдельно, геометрия компилируется снова для текущей позы.

Проверки: `semantic-intent.test.mjs`, `semantic-plan-regression.test.mjs` (полный план + все кадры перехода/idle сохраняют кости вне правой ноги), `local-leg-intent.test.mjs`, `motion-intent.test.mjs`, `contact-language.test.mjs`, `motion-semantic-search.test.mjs`. Имеющийся `command-naturalness.test.mjs` падает до языкового блока на `clipSemantics(layer).layerOnly`; эта семантическая классификация в данном изменении не редактировалась.

Ограничения: свободный язык по-прежнему может быть неверно интерпретирован моделью; локальный компилятор не является универсальным решателем анатомии. Разбор проверен на составных сменах позы, перемещении/повороте, контактах и свободной активности; качество каждой конечной траектории определяется прежним планировщиком.

Повторный проход финального промпта: 0.95–1.81 с без кэша на тех же шести командах. Проверка через живой HTTP API «Подними правую ногу»: разбор 1.52 с, весь план 1.95 с (HTTP 2.07 с), status ready, локальная маска только правой ноги. Артефакт `artifacts/semantic-parser-v1/live-api-plan.json`.

## Посадка и полное время — 2026-10-23, после пользовательской проверки

Исходный живой запрос «сесть» сохранён в `artifacts/sitting-regression/before-{request,response}.json`: язык 0.95 с, подбор 0.72 с, коррекция 1.34 с, траектория 2.18 с, всего 5.39 с. Выбран `f_undou_00_03`; правая стопа позади таза (-.111H), правое колено 157°. Низкий таз сам по себе допускал такую позу.

`tools/neutral-seat.mjs` добавляет мягкие предпочтения для обычной посадки без указаний на ноги: стопы перед тазом, без чрезмерного складывания коленей и выноса стоп вбок. Это ранжирование, не новые обязательные условия и не назначение одного клипа. Явные задачи ног, опоры на предметы и продолжаемые действия не получают этого предпочтения. Если выбранный целый библиотечный кадр уже имеет спокойно расположенные руки, не запускается сторонняя коррекция рук. На сохранённом запросе выбрался `LL_WLoop`, стопы .206H вперёд, колени 138°; прежнего складывания ноги назад нет.

Расчёт контактных сил: базисы контактов вычисляются один раз, рабочие буферы переиспользуются; 160 итераций сохранены. `contact-forces-fast.test.mjs` сравнивает силы, остатки и допустимость на 80 случаях с прежней реализацией (включая наклонные опоры и скольжение), допуск 1e-8; отдельный микрозамер 558→211 мс. Копирование упакованных траекторий заменено на копирование числовых p/q/s-массивов; точность и независимость копий проверяет `packed-frame-clone.test.mjs`.

Живой повтор ТОГО ЖЕ запроса после перезапуска: первый план 4.90 с (HTTP 5.40 с), повторный 1.20 с (HTTP 1.46 с), язык в обоих из кэша. Поэтому универсальное ускорение первого запроса НЕ подтверждено: остаётся существенная стоимость холодного подбора и подготовки траекторий. Артефакты `live-0.json`, `live-1.json`. Профиль `profile.cpuprofile` выявил клонирование траекторий и контактный solver; он снят до замены клонирования.

При проверке из свежего интерфейса модель разбора добавила не запрошенный стул. Компилятор теперь отбрасывает самовольно добавленные контакты с предметами и трактует такую посадку как обычную на пол; явная команда со стулом сохраняет опору. Это проверяется в `semantic-intent.test.mjs`.

Дополнительная визуальная проверка выявила у первого нового донора запрокинутую голову. Мягкое ранжирование обычной посадки дополнено нейтральным `faceUp`, предпочтением более низкого таза и меньшего сгиба коленей. На сохранённом запросе итоговый донор `L_M_Loop`: faceUp -.041, таз .109H, стопы .299/.361H впереди, колени 125/122°. Это предпочтение обычной посадки, а не ограничитель всех сидячих поз. Последний холодный запуск с фиксированным смыслом всё ещё 7.22 с, тёплый 1.44 с — общая проблема холодной подготовки остаётся.

Холодный профиль подтвердил дорогую подготовку `selectionBank` и траекторий. `warmTransitionPaths(catalog, rows)` теперь до готовности стенда подготавливает также уже описанные нейтральные переходы без предметов (те же условия confidence>=.5), а не только пять измеренных пилотов; группировка кадров тоже готовится заранее. Кэши путей/анализа расширены до 64. Ни кандидаты, ни проверки не сокращены. Стоимость переносится в запуск сервера; остальные неизвестные клипы остаются в прежнем поиске.

Регрессия после этой подготовки: первый план с фиксированным смыслом 3.27 с вместо 7.22 с до подготовки, повторный 1.76 с. Языковой запрос в этих цифрах отсутствует. Итоговый донор/геометрия не изменились. Универсальные 3 с от ввода до движения пока не обеспечены.

Финальный первый запрос из интерфейса после перезапуска с подготовленными 45 переходами: старт 3.57 с, всего 3.77 с; разбор 0.02 с из кэша, план 3.28 с. Посадка визуально проверена, артефакт final-live.json. Без кэшированного языкового ответа к этому добавится время сети/модели.

### Наклон в поле posture

Ошибка на запросе «наклониться вперёд, руки на ягодицы»: свободное `posture: leaning forward` ошибочно считалось неизвестной полной позой, хотя тот же смысл в `parts: torso / lean forward` уже поддерживался. Перед компиляцией направленный наклон теперь нормализуется в изменение корпуса. Прежние цели рук сохраняются, а наклон сидя/на коленях добавляет сохранение текущей опоры. Проверка `tools/lean-semantic.test.mjs` сравнивает оба формата на трёх исходных опорах и проверяет обе кисти.
