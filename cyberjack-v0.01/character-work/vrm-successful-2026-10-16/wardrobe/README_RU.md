# Гардероб: вещи отдельно от тела · PoC 2026-10-20

Первая рабочая версия: одежда вынута из запечённых VRM в отдельные GLB и пришивается к телу в рантайме.
Проверено числом и глазами (`preview-poc.png`).

## Что получилось

| | было | стало |
|---|---|---|
| Mira, все комплекты | 4 VRM × 69–82 МБ ≈ **300 МБ** | тело (outfit_03) + **14 вещей, 25 МБ** |
| смена вещи | загрузка 70–80 МБ VRM, сброс позы | подмена скелета у готового меша (микросекунды) |
| комбинации | 4 готовых комплекта | любые сочетания слотов |

Вынуто из `Mira_outfit_00/01/02`: 14 вещей, слоты `top` (4), `bottom` (1), `underwear_top` (2),
`underwear_bottom` (1), `socks` (1), `shoes` (1), `accessory` (4). Каждая вещь — 0.22–4.95 МБ
(доминируют текстуры, геометрия 0.1–0.3 МБ).

## Состав

```
wardrobe/
  wardrobe.json                 — манифест: id, слот, материал, источник, boneset, вес
  items/mira/<id>.glb           — по одной вещи: её примитив + материалы/текстуры + заглушки костей
  qa-wardrobe.html              — стенд: тело + пришитые вещи против нативного аутфита
  extract_garments.py           — генератор (в tools/wardrobe/)
  preview-poc.png               — кадр проверки
```

`wardrobe.json`: `{format: 'cyberjack-wardrobe-v1', character, boneset: {joints, hash}, items: [...]}`.
`boneset.hash` — sha256 имён костей: вещь годится только тому скелету, у которого тот же хеш.

## Как пришивать (проверенный рецепт)

```js
const base = await loader.loadAsync('characters/mira/Mira_outfit_03.vrm');   // тело без одежды
const bodyMesh = /* любой SkinnedMesh модели — у них общий скелет */;
const item = await loader.loadAsync('wardrobe/items/mira/mira-00-kk-pufferlong-8400.glb');
const mesh = /* первый Mesh из item */;
mesh.skeleton = bodyMesh.skeleton;                 // ← вся суть: скелеты идентичны
mesh.bindMatrix.copy(bodyMesh.bindMatrix);
mesh.bindMatrixInverse.copy(bodyMesh.bindMatrixInverse);
base.scene.add(mesh);                              // вешать на корень модели, не на группу тела
```

## Итоговая примерка

`qa-final.html` → `preview-final.png`: шесть состояний из одного тела — полный комплект, микс с топом из zipmod,
бельё, платье (2 части), только обувь+чулки, нудес. Все слоты независимы, клиппинга и пустых панелей нет.

## Что проверено

1. **Скелеты:** 971 кость у всех четырёх аутфитов Mira (Kai — 960), имена совпадают, `inverseBindMatrices`
   совпадают побайтово, rest-трансформации совпадают полностью. Поэтому вещь переносится без ре-экспорта.
2. **Точность вырезания:** у вынутой вещи сырые вершины, `skinIndex`, `skinWeight` и IBM совпадают с оригиналом
   бит-в-бит (delta = 0).
3. **Точность пришивания:** если нативный меш той же вещи пересадить на скелет тела, его вершины совпадают
   с пришитой копией — **max 0.00000 м, среднее 0.00000 м** на 1195 вершинах.
   (Сравнение двух разных инстансов модели даёт ~1 см — это разница поз/нормализации инстансов, а не ошибка сшивания.)
4. **Визуально:** куртка из `outfit_00` + шорты из `outfit_01` на теле `outfit_03` сидят по фигуре,
   без дырок и провалов (статичный кадр, см. `preview-poc.png`).

## Маска тела: не нужна (проверено 2026-10-20)

Планировалась композиция AM-масок в рантайме, но в этих VRM масок просто нет:

- текстуры материала тела (`img21/22/23`) **побайтово одинаковы** у `outfit_00` и `outfit_03` (sha совпадает),
  альфа у базовой текстуры — **255 во всех пикселях** (0.00% пикселей < 255);
- геометрия тела идентична: 11 примитивов, **13 942 вершины, 75 174 индекса** в обоих файлах;
- маски, которые запекались в пайплайне (`mira_body_outfit02_*_outermask.png` в `Documents/Codex/…/textures`),
  в VRM не попали — вещи KK и так сидят по фигуре.

Вывод: прятать кожу под одеждой не нужно, пока гардероб состоит из облегающих вещей KK. Понадобится только
для свободных вещей (платья с разрезами, халаты) — тогда возвращаемся к §3 дизайн-документа.

**Физика:** групп пружин во всех четырёх VRM ровно **11** и они одинаковы, включая нудес — то есть одежда
своих цепочек не добавляет (у Kai в `outfit_00` они есть, у Mira — нет). Переносить в менеджер пока нечего.

## Вещь может состоять из нескольких частей

В `outfit_02` «топ» на самом деле **платье из двух примитивов** с одним базовым именем материала:

| id | bbox по Y | что это |
|---|---|---|
| `mira-02-kk-cf-top-aonep-m-8372` | 0.713–1.107 | низ: бёдра → талия |
| `mira-02-kk-cf-top-aonep-m-8412` | 1.082–1.375 | верх: талия → плечи |

Раньше правило «слот по имени материала» ставило оба в `top`, и надевание одной вещи показывало только низ —
в кадре это выглядело как «зелёная юбка без верха». Теперь:

- в манифесте у вещей есть `group` (базовое имя материала без хвостового номера), `part`, `parts`;
- слот группы пересчитывается по геометрии: если части вместе покрывают бёдра (`y < 0.95`) и грудь (`y > 1.25`) —
  это `dress`, а не `top`;
- `Wardrobe.equip(id)` надевает **всю группу** сразу, `detail` показывает число частей на слот.

Такие же группы: `kk-acs-m-haibisukasu` (2 части, слот `accessory`, y 1.49–1.62 — украшение волос).

## API

```js
import {Wardrobe} from './wardrobe.js';
const w = new Wardrobe(vrm);                    // vrm = загруженная база без одежды
await w.init('./wardrobe.json');                // манифест
await w.setOutfit({top: 'mira-00-kk-pufferlong-8400', shoes: 'mira-00-kk-m-cf-shoes-steampunk00-8900'});
w.unequip('top'); w.state                       // {bottom: '…', shoes: '…'}
```

Правила внутри: один предмет на слот (кроме `accessory`), порядок отрисовки по слоту
(`underwear → socks → bottom → top → shoes → accessory`), проверка `boneset.hash` (вещь под чужой скелет не наденется).

## Чего пока нет

1. **Маска тела.** Сейчас тело берётся из `outfit_03` — оно не маскировано ни под какую одежду, поэтому под
   курткой остаётся голая кожа. Для «одел → кожа спрятана» нужно вынести AM-маски в рантайм:
   `alpha = baseAlpha × Π(1 − mask_вещи)` по надетым вещам (см. `characters/WARDROBE_RU.md` §3).
2. **Слоты и правила.** У вещей проставлен слот, но нет правил «одновременно только один top», «бельё под низом»,
   порядка слоёв и `renderOrder` для cutout-материалов.
3. **Физика.** Юбки/цепочки не переносятся: `VRMC_springBone` живёт на уровне VRM. Сейчас в гардеробе только
   вещи без собственной физики; для юбки нужно добавлять цепочки в `springBoneManager`.
4. **Kai.** Не вынут: у него в наборе есть генитальные примитивы (`cm_m_dan_f`, `cm_m_dankon`), которые
   по умолчанию отфильтрованы флагом; для выгрузки — `--keep-genital`.

## Одежда прямо из zipmod Koikatsu (проверено 2026-10-20)

`tools/wardrobe/extract_zipmod_garment.py` вынимает вещь из мода игры в GLB, пригодный для этого гардероба.

```bash
python3 tools/wardrobe/extract_zipmod_garment.py \
  --vrm characters/mira/Mira_outfit_03.vrm --rig animations/source_rigs.json \
  --zipmod ".../mods/Sideloader Modpack/[mat]Tops v1.1.zipmod" \
  --mesh o_top_ofcard_a --slot top --out wardrobe/items/kk --id kk-tops-ofcard-a
```

Что получилось на `[mat]Tops v1.1`:

| | значение |
|---|---|
| меш | `o_top_ofcard_a`: 3 145 вершин, 13 506 индексов, **100 костей** в SkinnedMeshRenderer |
| сопоставление костей | **0 костей без цели в VRM** (правило: имя → cf_s_/cf_j_ ↔ humanoid → предок) |
| потерянных вершин | 1 (нулевые веса) |
| вес GLB | 0.25–0.30 МБ на вещь |
| текстура | у этой вещи `_MainTex` пустая → плоский цвет (0.55/0.5/0.62) |

**Три вещи, без которых не работает** (все три ловушки были пойманы замером):

1. **Вершины KK лежат не в bind-пространстве тела.** Нужен перенос `v_body = Σ wᵢ · (Wᵢ · Bᵢ) · v`,
   где `W` — мировые матрицы rest-скелета нашего рига (`animations/source_rigs.json`), `B` — `mesh.m_BindPose`
   из бандла. Без этого вещь висит вокруг начала координат (bbox ±0.13 м вместо груди 1.03–1.39 м).
2. **Веса брать из `mesh.m_Skin`, а не из канала 7 потока.** Канал 7 с `dimension=4, offset=24` выглядит как
   blendWeights, но сумма по нему не равна 1 (0…1.015) — после переноса вершины улетают на километры.
   В `m_Skin` лежат `boneIndex_0..3` и `weight_0..3`, сумма ровно 1.
3. **Потоки интерливованные:** stride 40 байт (позиция 0, нормаль 12, «канал 7» 24) + stride 20 (UV по смещению 4).
   Читать как `np.frombuffer(...).reshape(n, stride/4)` и брать столбцы, а не подряд идущие тройки.

**Варианты `_a` / `_b` — это размеры груди**, а не дубли. На Мире вариант `a` даёт заметный клиппинг по груди,
`b` садится. В манифесте стоит держать оба и выбирать по параметру тела персонажа.

## Подгонка по телу: `tools/wardrobe/fit_to_body.py`

**Почему грудь «лежит как на плоской».** В VRM Миры кости груди стоят ровно так же, как в rest-скелете:
`cf_s_bust01_L` расходится на 2.9 мм, `cf_s_bust02_L` — 0.4 мм, `cf_j_bust03_L` — 0.2 мм. То есть **объём груди
запечён в геометрию тела, а не в кости**. Одежда из KK держится на костях — она физически не может повторить
объём, которого в скелете нет. Поэтому лечится только в пространстве меша, параметрами экспорта.

```bash
python3 tools/wardrobe/fit_to_body.py --glb wardrobe/items/kk/kk-tops-ofcard-b.glb \
    --vrm characters/mira/Mira_outfit_03.vrm            # зазор 2.5 мм, сглаживание 8
```

| параметр | по умолчанию | что делает |
|---|---|---|
| `--clearance` | 0.0025 м | требуемый зазор до поверхности тела |
| `--max-dist` | 0.03 м | трогать только вершины ближе этого к телу (рукава и подол не задеваются) |
| `--pull-dist` | 0.012 м | висящие ближе этого притягивать к телу, а не только выталкивать провалившиеся |
| `--smooth` | 8 | сглаживание поля сдвига по рёбрам меша — ткань облегает, а не встаёт панцирем |
| `--passes` | 3 | итерации; на третьем проходе сдвиги уже < 2 мм |
| `--push-max` | 0.05 м | предохранитель от выбросов |

Страховочный дожим в конце гарантирует: ни одна вершина не остаётся глубже поверхности тела.

**Замеры**

| вещь | вершин внутри до | после | зазор медиана |
|---|---|---|---|
| `kk-tops-ofcard-a` | 1459 | 173 (касание, 0 мм) | 3.1 мм |
| `kk-tops-ofcard-b` | 972 | 112 (касание, 0 мм) | 2.7 мм |
| нативная куртка `mira-00-kk-pufferlong` | 20 | 14 (касание, 0 мм) | 20.4 мм |

Нативные вещи тоже слегка касаются тела (те самые 20 вершин) — тот же проход их закрывает.
`preview-fit.png` — крупный план груди: до / после для варианта `b`, вариант `a` и нативный аутфит.

| вещь | источник | вершин | bbox по y, м | что это |

| `kk-line-socks` | `[dam]Line Socks` → `o_socks_knee01` | 1380 | 0.01–0.71 | гольфы до колена |
| `kk-tophat` | `[Augh] Top Hat v1.0.0` → `hatto` | 6250 | 1.42–1.67 | цилиндр; одна кость `root` → `--force-bone root=cf_j_head` |
| `kk-collar` | `[DeathWeasel]Collars v1.0` → `o_top_maid_01_a` | 585 | 1.39–1.52 | воротник на шею, 12 костей |

Новые слоты в манифесте: `head`, `neck`. Всего вещей — 22. `preview-new-items.png` — четыре комбинации.

**Про аксессуары на голову: у них одна кость `root`,** поэтому нужен `--force-bone root=cf_j_head`
(и `root=cf_j_neck` для шеи). Проверка посадки — по bbox: шляпа 1.42–1.67 при верхе тела 1.604,
зазор до поверхности 0.9 мм, то есть сидит на волосах, а не висит.

**Плотные вещи (колготки, шорты) проваливаются в тело** — та же причина, что с грудью: обхват тела больше,
чем у вещи. Обувь (max 5.1 мм) и воротник держатся нормально.
