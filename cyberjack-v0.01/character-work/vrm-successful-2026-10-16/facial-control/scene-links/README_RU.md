# Связь движения тела с мимикой

Раньше мимика и связанные движения тела во вьювере управлялись отдельно. Теперь в «Связанных действиях» по умолчанию включено «Лицо по игровым таблицам сцены»: состояние тела выбирает исходные правила дыхания/выражения, а они — морфы лица. Это не лицевые AnimationClip и не случайный набор эмоций для позы.

Профиль взят из KK_CharacterInfoData.json каждого экспорта: Rin Personality8 → c08, Mira Personality40 → c40. Из сохранённых animation-links/sources/h/list/*.unity3d извлечены HFaceList соответствующих профилей, personality_breath и breath-правила. По исходному FaceListCtrl.LoadInfo и HVoiceCtrl.LoadBreathPtn таблицы обходятся в сортированном порядке бандлов; строки с тем же ID/состоянием заменяют предыдущие. raw/ сохраняет исходные записи и происхождение, *.json.gz — эффективные таблицы.

Соответствие главного состояния базовому получено из членства клипов в BlendTree: например, L_A_Loop и L_A_Idle принадлежат базовому A_Idle. Префиксы не отбрасываются наугад. aliases.json.gz хранит связи для264вариантов сцен. Переход к форме идёт по цепочке «сцена/базовое состояние → breath_XX_00 → подходящие условия/lstAnimID → запись personality_breath профиля → lstFaceNormal/faceWeak → HFaceList». Варианты лица выбираются с исходными повторениями в списках; смена внутри состояния использует timeChangeFaceMin/Max. Не найденное правило или неподдержанная форма показываются явно, без подстановки похожей эмоции.

Включены глаза, брови, рот, ограничения открытия и моргание. Индексы игры и KKBP не отождествляются: native PtnSet сопоставлены с карточными формами по точным именам исходных blend shapes. Например, native mouth0 сопоставляется KKBP Open1. Переход формы использует существующие0.15с, изменение открытия —0.3с из FaceListCtrl.SetFace. Слова и пути звука сохраняются для происхождения; эти аудиозаписи здесь не извлекаются и не воспроизводятся. Аудиодрайвер выбранного пользователем файла по-прежнему доступен отдельно; он учитывает минимальное открытие рта сцены.

В «Контексте мимики» задаются условия просмотра: уровень реакции (порог50), индекс ветки personality.info0…3, активность/интенсивность движения и дополнительные флаги. Прогресс прохождения и точная реализация GetStateSelect из игрового сохранения не восстановлены: выбранная ветка используется явно. По умолчанию активность движения берётся из выбранного Loop/Idle, контакт — из дополнительной связки предмета и её фазы. Это контекст предпросмотра, а не утверждение о состоянии оригинальной игровой сессии. Поддержаны исходные условия -1,0…19; запрещающие90+ не проходят. Слабая реакция доступна при выбранном контакте и соответствующем native isWeakPointJudge. Одновременные voice-сценарии, проверки окончания звучания и прогресс игры целиком не исполняются.

Слёзы, динамический румянец, переключение highlight, eye shaking и gag-материалы сохранены в исходных данных, но не анимируются. Четыре native-формы каждого профиля не имеют подходящего поддержанного KKBP-морфа; соответствующие записи не выдаются за полноценное выражение. Настройки моргания/ширины бровей сохраняют ранее описанные ограничения базового facial-control. Отдельный управляемый язык имеет приоритет над формой рта сцены; глаза и брови продолжают следовать таблице.

При автоматической мимике ручные селекторы лица отключены и помечены как управляемые сценой. Для ручной настройки снимите флажок в панели сцены. Остановка действия освобождает управление и восстанавливает ручную мимику. Профиль обновляется при смене персонажа; при смене одежды веса перепривязываются к новой геометрии.

## Исчезающие части модели

Three.js использовал закэшированные границы мешей, рассчитанные в старой позе. После перехода в лежащую позу ошибочно отсекались лицо, волосы и одежда. У всех mesh в загруженном VRM отключён frustumCulled: для одного аватара это позволяет корректно показывать скелетную анимацию, морфы и SpringBone без пересчёта всех деформированных вершин каждый кадр. Face culling материалов, прозрачность и текстуры не менялись.

В reports/culling-before.json из24частей Mira отрисовывались лишь5–6 на восьми проверенных направлениях; после исправления во всех направлениях отрисовываются24части и120178треугольников. reports/face-link-qa.json проверяет переход между Loop/Idle и разными исходными face ID, соответствие native→KKBP, конечные веса морфов, восстановление ручных значений и профиль Rin после Mira. reports/models-unchanged.json подтверждает неизменные SHA256 VRM/.blend.

Повторное извлечение: `python3 facial-control/scene-links/tools/extract_scene_faces.py` (UnityPy); CHARACTER_BUNDLE не требуется при запуске внутри пакета, переменная CHARACTER_BUNDLE позволяет явно выбрать корень. Исходные таблицы уже сохранены в animation-links/sources, а нативные контроллеры — в facial-control/native-controllers.json. Разобранные FaceListCtrl, HVoiceCtrl, HFlag и HAibu сохранены в native-code/.

API: window.__studio.links.faceLink.state/profiles/rules/aliases; window.__studio.face.state.sceneFace показывает применённые формы и источник. setSceneFace(null) освобождает слой лица; основной контроллер сцены сделает это автоматически при остановке.
