# Лицевое управление Koikatsu → Rin/Mira

Извлечены исходные FaceBlendShape-контроллеры трёх базовых голов из bo_head_00.unity3d и карточные таблицы KK_BlendShapeInfo.json для Rin/Mira. Для каждого персонажа сохранены99паттернов:41глаз,17бровей и41рта, включая исходные имена, веса частичных морфов, сведения о специальных материалах и анимации текстур. Это параметрическое управление лицом, не библиотека AnimationClip.

В актуальном вьювере раздел «Лицо · Koikatsu»: независимые паттерны глаз/бровей/рта, степень открытия глаз/рта, сила выражения бровей, автоморгание, быстрые комбинации эмоций и сброс. Поддержаны87геометрических паттернов на каждом персонаже. Состояние сохраняется при смене одежды. Исходные VRM/Blender-файлы, текстуры и SpringBone не менялись.

Вьювер больше не вызывает VRMUtils.combineMorphs: эта оптимизация удаляла исходные морфы, оставляя лишь привязанные к VRM presets. Теперь доступны все151сохранённых морфов. Управление использует существующие объединённые морфы KKBP; закрытая/открытая поза глаз сопоставлена по native FBS Close/Open и именам исходного face mesh. Рот смешивает соответствующие Open/Closed-формы. Все конечные формы существуют во всех восьми актуальных VRM; отчёт reports/outfit-coverage.json.

Переход между паттернами — линейные0.15с из TimeProgressCtrl; ручной API может менять формы сразу. Моргание использует BaseSpeed0.15(+случайные0…0.05с), BlinkFrequency30 и паузу0.2×случайное целое из исходного FBSBlinkControl. Значения открытия квантуются до процента. Слайдер глаз меняет открытие относительно сохранённой карточной формы, а не восстанавливает сырые Unity blend shapes: исходный максимум персонажа уже запечён в объединённом KKBP-морфе. Брови имеют выбор паттерна и силу; точная исходная SyncBlink-деформация бровей отдельно не воспроизведена. VRM-взгляд и его поправки к векам не включались.

12специальных паттернов глаз требуют gag-геометрии, смены материалов или текстур (сердца, спирали и т.п.). Их данные извлечены полностью и доступны в каталоге, но варианты отключены в UI, чтобы не выдавать обычный морф за полноценный эффект. Речь от аудиофайла и отдельная библиотека языка подключены в performance/; сценовые сценарии не перенесены. Сочетания быстрых эмоций — комбинации для просмотра, не отдельные исходные игровые клипы.

Файлы: catalog.json — карточные профили и соответствия VRM; native-controllers.json — полные сериализованные контроллеры с именами target meshes и парами Close/Open; native-code/ — локально извлечённая логика; sources/ — исходный Unity-бандл; *-BlendShapeInfo.json — неизменённые карточные таблицы. provenance.json содержит происхождение и SHA256.

API вьювера:

```js
window.__studio.face.set({Eye: 1, eyesOpen: 0});
window.__studio.face.set({Mouth: 27, mouthOpen: 0.6});
window.__studio.face.set({Eye: 0, eyesOpen: 1, blink: true});
window.__studio.face.reset();
```

Индексы паттернов берутся из catalog.json соответствующего персонажа; неподдержанные варианты API отклоняет. Пользовательские сочетания не записываются в VRM-файл. Для повторного извлечения из сохранённых исходников: python3 facial-control/tools/extract.py из корня пакета (UnityPy).

Пока включён флажок лицевого управления, этот контроллер владеет лицевыми весами. Для прямого использования стандартного VRM expressionManager отключите флажок. Случайное изменение ширины рта при речи из FBSCtrlMouth не воспроизводится; исходные настройки сохранены.
