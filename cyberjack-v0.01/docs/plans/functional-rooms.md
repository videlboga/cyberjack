# Функциональные комнаты: Пост наблюдения + жилые камеры

> **Цель:** Убрать галлюцинации персонажей (Май «проверяла влажность», «записала спектрограмму», «проверила логи доступа» — всё выдумано) и дать им реальные факты, о которых можно говорить. Пост наблюдения сделать функциональным (данные активов, история, текущее состояние лаборатории, контракты). Жилые камеры — описание + минимальный интерьер + режим дня.

**Архитектура:** Контекст комнаты попадает в промпт через `spatial.description` (одна строка из `laboratory_rooms.description`) + `activeContextNames`. Сейчас `room.description` короткий и статичный, реальных данных нет → модель галлюцинирует.

---

## Текущее состояние

- **Пост наблюдения** (`room_control`): «Рабочее место ассистента, терминал телеметрии и управление оборудованием.» — декоративно, нет данных.
- **Жилая камера B** (`room_cell_b`): «Резервная жилая камера для второго актива.» — пусто.
- **Жилая камера A** (`room_cell_a`): «Закрытая камера с койкой, санитарным модулем и контролем сна.» — минимально.
- В `scene_objects` один объект (потолочный подвес). Реальных данных нет.

## План

### 1. Пост наблюдения — функциональный

Добавить в контекст комнаты **реальные данные**, которые персонаж видит на терминале:

**a) Данные активов** (из `subjects` + `subject_point_states`):
- Имя, статус, текущие параметры (sensitivity/capacity/openness/plasticity/attitude).
- Текущее состояние (tension, engagement, overload).
- Где находится (комната/устройство).

**b) История взаимодействий** (из `event_logs` / `chat_memory`):
- Последние события в лаборатории (кто с кем, что происходило).

**c) Текущее состояние лаборатории** (из `laboratory_assets` + `laboratory_room_assignments`):
- Кто в какой комнате, какие устройства заняты.
- Что сейчас происходит (процедуры, калибровка).

**d) Контракты** (из `asset_contracts`):
- Список контрактов активов, их статус.

**Формат:** новая функция `buildObservationPostContext(characterId)` → массив строк, которые добавляются в `scene.contexts` для персонажей в `room_control`.

### 2. Жилые камеры — описание + интерьер

**a) Богатое описание** комнаты (койка, санитарный модуль, освещение, температура).

**b) Минимальный интерьер** — объекты в `laboratory_assets` или `scene_objects`:
- Койка, санитарный модуль, небольшая аппаратура (музыка, свет).
- Персонаж может включить музыку (действие).

**c) Минимальный режим дня** — расписание (подъём, приёмы пищи, отбой), которое персонаж знает и может обсуждать.

## Верификация

- `npx tsc --noEmit` — чисто.
- `npx vitest run` — 620+ тестов зелёные.
- Изолированный прогон: Май-Ника в Посте наблюдения говорят о реальных данных (телеметрия активов, история), а не галлюцинируют.
- Жилые камеры: персонажи обсуждают интерьер, режим дня, музыку.

## Риски / открытые вопросы

1. **Объём контекста** — не перегрузить промпт; Пост наблюдения даёт много данных, нужно сжато.
2. **Режим дня** — как реализовать (статичное расписание vs динамическое)? Рекомендую статичное + привязка к `worldMinute`.
3. **Интерьер** — объекты как `laboratory_assets` (с действиями) или просто описание? Рекомендую `laboratory_assets` с действием «включить музыку».
