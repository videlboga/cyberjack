# Переработка системы памяти: иерархия опыта + темы из памяти

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Заменить «эпизод как кусок по id» на детерминированную иерархию опыта (глава → эпизод → момент), пересадить генерацию тем разговора на живую память и убрать пластик повторяющихся разговоров.

**Architecture:** Сейчас память — это плоский слой атомов (`memory_embeddings`), агрегируемых в «эпизоды» по техническим порогам (id-разрыв ≤12, те же участники). Это нестабильно и не отражает реальную структуру опыта. Новая модель — **4 слоя** (убеждения / биографические факты / отношения / опыт) + **иерархия опыта** (глава → эпизод → момент) с детерминированными границами. Темы разговора берутся из памяти пары, а не из статичных крючков.

**Tech Stack:** TypeScript, better-sqlite3, Vitest.

**Ветка:** `feat/localization`. Есть незакоммиченные изменения (db.ts, socialTransactions.ts, autonomousScene.ts) — перед стартом зафиксировать состояние.

## Контекст: что уже есть (не перепроверять)

### Текущие слои памяти
- `memory_embeddings` — атомы (`episode_v2`): text, tags, related_subjects, metadata (actionId, pointId, реплики, observation, objectiveFacts). Пишутся в `recordMemoryEvent` (`memoryLayer.ts`).
- `subjective_memory_episodes` — LLM-эпизоды (`SubjectiveEpisode`): title, summary, appraisal, agency, emotionalArc, **associations**, openLoops, tagExpansions. Генерируются в `queueSubjectiveEpisode` (`subjectiveMemoryEpisodes.ts`), 2 LLM-вызова на эпизод.
- `social_memories` — отношения/обещания между персонажами (`socialMemory.ts`).
- `social_threads` — треды разговоров (from_id, to_id, topic, status, salience, source_json).
- `character_relations` — числовые отношения (attitude, openness, familiarity_level, general_opinion, recent_memories).

### Ключевые функции
- `aggregateMemoryEpisodes` (`memoryEpisodes.ts`) — склейка атомов в эпизоды по id-порогу ≤12 + участники + контейнер.
- `memoryThemesForPair` (`socialTransactions.ts`) — темы из эпизодов (`memory.title` → topic) + openLoops → намерения.
- `chooseTopic` (`socialTransactions.ts`) — выбор темы: 60% продолжить активный тред, иначе из пула (крючки + биография + memory-темы).
- `queueSubjectiveEpisode` / `applySubjectiveIntervention` / `regenerateSubjectiveEpisode` (`subjectiveMemoryEpisodes.ts`).
- `materializeNextSubjectiveMemory` (`subjectiveMemoryWorker.ts`) — воркер, очередь `memory.materialize`.

### Проблемы (диагноз)
1. **Границы эпизодов нестабильны** — по id-разрыву ≤12, а не по смыслу. Параллельные записи рвут один разговор на два эпизода.
2. **Нет иерархии** — эпизоды не связаны (нет «родитель → дочерние»). «Разговоры с Никой» и «диалог о семье» — независимы.
3. **Эпизоды не эволюционируют от разговоров** — associations меняются только через кресло, не от прожитых диалогов.
4. **Темы из статичных крючков** конкурируют с memory-темами и чаще выигрывают → пластик.
5. **Треды не закрываются** — turnCount не инкрементируется, тред живёт вечно, тема повторяется.

## Целевая модель

### 4 слоя (разные скорости изменения)

| Слой | Что | Скорость | Хранилище |
|---|---|---|---|
| **Убеждения** | взгляд на жизнь, выводы | медленно | `character_relations.general_opinion` + новый `beliefs` |
| **Биографические факты** | изначальная история | статично | атомы `biography` (пересадить с текста) |
| **Отношения** | пер-пер связи | эволюция | `character_relations` + `social_memories` |
| **Опыт** | главы → эпизоды → моменты | непрерывно | `memory_embeddings` + `subjective_memory_episodes` |

### Иерархия опыта

```
ПЕРИОД БОДРСТВОВАНИЯ (от сна до сна) = ГЛАВА
  └─ граница: сон (персонаж заснул, sleep_state → 'sleeping')
  └─ внутри — эпизоды по смыслу:
      ├─ ЭПИЗОД: разговор (тред)
      ├─ ЭПИЗОД: физика/процедура
      └─ ЭПИЗОД: команда/наблюдение
  └─ ВО ВРЕМЯ СНА — агрегация (консолидация памяти):
      ├─ разбить период на эпизоды по смыслу
      ├─ сформировать/обновить эпизоды (LLM)
      ├─ обновить отношения (familiarity/attitude)
      └─ обновить убеждения (если были сильные события)
```

### Детерминированные границы

| Уровень | Граница | Сигнал |
|---|---|---|
| **Глава (период бодрствования)** | сон | `sleep_state` → `'sleeping'` (переход в `advancePhysiology`) |
| **Эпизод** | смена смысла внутри периода | смена темы/действия/локации/процедуры (threadId, actionId, pointId, container) |
| **Момент** | смена действия внутри эпизода | actionId, pointId |

**НЕ границы:** оргазм/разрядка (пик, их много), смена локации внутри эпизода, вход/выход второстепенных участников.

### Ключевой принцип: сон = время агрегации

Сон — не просто граница, а **момент консолидации памяти** (как у людей). Персонаж не действует во сне, поэтому это идеальное окно для переработки: разбить период бодрствования на эпизоды по смыслу, сформировать/обновить их (LLM), обновить отношения и убеждения. Один батч в сутки вместо непрерывных LLM-вызовов — дешевле и физиологичнее.

Триггер: переход `sleep_state` → `'sleeping'` в `advancePhysiology` (`physiology.ts`). **Консолидация происходит ТОЛЬКО во сне** — никакой принудительной агрегации в бодрствовании.

**Сон = граница дня, но эпизод может охватывать несколько дней.** Сон всегда закрывает день (период бодрствования), но эпизод — смысловая единица, которая может агрегироваться из нескольких дней. Пример с Эли: три дня в капсуле = один эпизод, хотя было три сна. LLM-разметка объединяет атомы из нескольких дней в один эпизод, если это один непрерывный опыт (капсула/устройство).

**A3. Эпизоды размечаются LLM по смыслу (один запрос).**
- Вместо эвристик по id/участникам — **LLM-разметка**: один запрос на период бодрствования, который разбивает атомы на эпизоды по смыслу (смена темы/действия/локации/процедуры). Эпизод может охватывать несколько дней (капсула/устройство).
- Test: LLM-разметка объединяет атомы из нескольких дней в один эпизод, если это непрерывный опыт.

**A4. Триггер агрегации при переходе в сон.**
- В `advancePhysiology` (`physiology.ts`): при `sleep_state` → `'sleeping'` — поставить задачу `memory.consolidate`.

## Риски и компромиссы

- **LLM-затраты**: консолидация во сне = один батч в сутки на персонажа (вместо непрерывных вызовов). Это дешевле текущей схемы. Если персонаж не спит (принудительное бодрствование) — консолидация откладывается до следующего сна; это осознанный компромисс (память копится, но не обрабатывается).
- **Миграция**: существующие `subjective_memory_episodes` без parentKey — обработать как «сирот» (привязать к периоду по времени).
- **Совместимость**: `memoryThemesForPair` и `chooseTopic` меняют поведение — проверить, что не ломают существующие social-тесты.
- **Объём**: это несколько дней работы. Этапы A+B+C — ядро; D+E — отдельные заходы.
